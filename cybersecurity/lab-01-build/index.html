CYBERSECURITY LAB 01

Building the Cybersecurity Lab

Designing, deploying, networking, and validating an isolated virtual environment for hands-on cybersecurity experimentation.

← All Labs Full Technical Documentation

OVERVIEW

Building the Foundation

This lab established the virtual infrastructure used throughout my cybersecurity home lab. The environment was designed to provide a controlled platform for offensive security, defensive security, detection engineering, Active Directory, and future cloud security exercises.

The lab uses Oracle VirtualBox with separate NAT and Host-Only networking. Internet access is available where required for system updates and package installation, while security testing traffic remains isolated within the Host-Only network.

OBJECTIVES

What I Built

Virtual Infrastructure

Built a reproducible multi-system cybersecurity environment using Oracle VirtualBox.

Network Isolation

Configured an isolated Host-Only network for controlled security testing.

Multiple Platforms

Established Linux and Windows systems representing attacker, server, endpoint, and vulnerable-target roles.

Validation

Verified addressing, routing, connectivity, and network behavior before beginning security testing.

LAB ARCHITECTURE

Network Design

The lab uses two network interfaces to separate normal internet access from security testing traffic.

NAT Adapter

Provides internet access for systems requiring operating system updates, package downloads, or other external resources.

Host-Only Adapter

Provides isolated communication between the lab systems without exposing intentionally vulnerable systems to the external network.

IMPLEMENTATION

Building the Environment

1. Virtual Machine Deployment

Deployed Kali Linux, Ubuntu Server, Windows Server 2022, Windows 11 Pro, and Metasploitable 2. Each system was assigned resources appropriate to its intended role.

2. Network Adapter Configuration

Configured NAT connectivity where internet access was required and Host-Only networking for isolated lab communication. Metasploitable 2 was restricted to the Host-Only network.

3. Static IP Configuration

Assigned predictable static addresses within the 192.168.56.0/24 Host-Only network.

4. Snapshots

Created VM snapshots after initial installation and successful boot verification to provide restore points before security testing and configuration changes.

TROUBLESHOOTING

Problems Investigated

Kali Interface Mapping

The NAT and Host-Only adapters did not map to the expected Linux interface names. I used ip addr, ip route, nmcli device status, and nmcli connection show to identify the correct interfaces and restore the intended configuration.

Windows Network Status

Windows reported the Host-Only adapter as disconnected despite successful communication. Testing with actual network traffic demonstrated that the status indicator did not represent an actual connectivity failure.

Windows 11 ICMP

Windows 11 initially blocked ICMP traffic from Kali. Investigation isolated the issue to the Windows Defender Firewall configuration, after which connectivity testing succeeded.

ANALYSIS

Lessons Learned

Building the environment reinforced the relationship between hypervisor networking, guest operating system interfaces, routing, and endpoint security controls.

Troubleshooting was driven by evidence from multiple diagnostic tools rather than assumptions. This was particularly important when Linux interface names did not match the expected adapter order and when Windows reported a misleading network status.

The completed environment provides a controlled foundation for progressively more advanced offensive and defensive security exercises.
